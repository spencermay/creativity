# Creator-Appraiser: Conceptual Creativity as Meta-Learning

A PyTorch implementation of the Creator-Appraiser framework from:

> Ren (2026). *Seeking the Unfamiliar but Memorable: Conceptual Creativity as Meta-Learning.*

This project operationalizes conceptual creativity as an optimization problem: given a pre-trained generative model (Creator) and a pre-trained evaluator (Appraiser), find outputs that are simultaneously **unfamiliar** (hard for the Appraiser to reconstruct initially) and **memorable** (easy to learn after a short adaptation).

## How It Works

### Overview

The system has two components, trained independently then composed:

1. **Creator** — A class-conditional DDPM (denoising diffusion probabilistic model) trained on MNIST. After pre-training, its weights are frozen. During the creative phase, we optimize the *noise inputs* (latent z) to the DDPM, searching for images that maximize a creativity reward.

2. **Appraiser** — An autoencoder trained on MNIST reconstruction. After pre-training, the encoder and most of the decoder are frozen. Only the *first decoder layer* (phi) is adaptable. This layer is reset to its initial state (phi0) before evaluating each candidate image.

### Creativity Reward

For a candidate image `c` generated by the Creator:

1. Reset Appraiser's first decoder layer to phi0.
2. Record `l0` = reconstruction loss on `c` (measures unfamiliarity).
3. Run T gradient steps adapting the first decoder layer to minimize reconstruction loss on `c`.
4. Record `lT` = reconstruction loss after adaptation (measures memorability).
5. Compute reward:

```
R = (l0 - lT) * exp(-(l0 - mu)^2 / tau^2) * exp(-lT / tau)
```

Where:
- `l0 - lT` is the **learnability gap** (how much the Appraiser improved).
- `exp(-(l0 - mu)^2 / tau^2)` is the **novelty bonus** — a Gaussian centered at mu, rewarding images with a target level of initial surprise.
- `exp(-lT / tau)` is the **memorability bonus** — rewards low final loss (the Appraiser actually learned the image).

### Creative Image Generation (Meta-Learning Loop)

Each creative image is produced by K steps of noise optimization:

```
for k = 1 to K:
    1. Denoise x_T through frozen DDPM → candidate image c
    2. Evaluate c with Appraiser → compute reward R
    3. Backprop through denoising path, update x_T to maximize R
```

After K steps, the final image is the creative output. The Creator resets to fresh random noise for the next image.

## Usage

### Full Pipeline (Pretrain + Warmup + Generate)

```bash
# First run: trains DDPM and Appraiser, caches checkpoints, then generates creative images
python scripts/train.py --config configs/fast.yaml

# Subsequent runs: loads cached warmup, jumps straight to creative generation
python scripts/train.py --config configs/fast.yaml
```

### Visualize Baseline DDPM Samples (No Creativity)

```bash
# See what the DDPM generates without any creative guidance
python scripts/sample_baseline.py --config configs/fast.yaml

# Try different guidance scales
python scripts/sample_baseline.py --config configs/fast.yaml --guidance_scale 1.0
python scripts/sample_baseline.py --config configs/fast.yaml --guidance_scale 3.0
```

### Visualize Creative Images

```bash
# Generate and visualize creative images with reward curves
python scripts/visualize.py --config configs/fast.yaml --n_images 6 --K 50

# Specific digit classes
python scripts/visualize.py --config configs/fast.yaml --classes 0,3,5,7 --K 100
```

### Override Parameters via CLI

```bash
python scripts/train.py --config configs/fast.yaml \
    --creator.guidance_scale 3.0 \
    --meta.K 100 \
    --reward.mu 0.8
```

## Training Phases

| Phase | What happens | Time (CPU, fast config) | Cached? |
|-------|-------------|------------------------|---------|
| 1. Creator pretrain | DDPM learns to generate MNIST digits | ~34 min | Yes |
| 2. Appraiser warmup | Autoencoder learns to reconstruct digits | ~10 min | Yes |
| 3. Creative generation | Noise optimization with reward signal | ~5 min (10 images) | No |

After the first run, Phases 1-2 are skipped (loaded from cache). Only Phase 3 runs.

## Key Parameters

| Parameter | Description | Default |
|-----------|-------------|---------|
| `creator.timesteps` | Diffusion schedule length | 200 |
| `creator.sample_skip_steps` | Stride for sampling (fewer = better quality, slower) | 5 |
| `creator.guidance_scale` | Classifier-free guidance (1.0 = none, >1.0 = stronger class signal) | 2.0 |
| `appraiser.inner_steps` | T: adaptation steps for Appraiser per image | 10 |
| `appraiser.inner_lr` | Learning rate for Appraiser first-layer adaptation | 0.01 |
| `reward.mu` | Target initial loss (center of novelty Gaussian) | 1.0 |
| `reward.tau` | Temperature/width of novelty Gaussian | 0.5 |
| `meta.K` | Noise optimization steps per creative image | 50 |
| `meta.outer_lr_creator` | Learning rate for noise optimization | 0.01 |

## Architecture Details

### Creator (DDPM)

- UNet denoiser with sinusoidal time embeddings + class embeddings
- ResBlocks with GroupNorm + SiLU activation
- Skip connections between encoder and decoder paths
- Cosine noise schedule (better for fewer timesteps)
- Differentiable sampling via deterministic DDIM-style steps (enables noise optimization)
- Classifier-free guidance at sampling time

### Appraiser (Autoencoder)

- Encoder: Conv blocks → latent vector (frozen after warmup)
- Decoder: latent → reconstruction, with a separable `first_layer`
- Only `decoder.first_layer` is adaptable during creativity evaluation
- `phi0` (initial first_layer weights) saved after warmup, restored before each evaluation
